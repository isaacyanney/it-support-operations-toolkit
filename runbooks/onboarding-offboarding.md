# User Onboarding and Offboarding Runbook

A control-focused checklist for preparing and recovering workplace technology. Adapt it to the employer's identity, security, data-retention and approval policies.

## Onboarding

### Request validation

- [ ] Approved request and start date received
- [ ] Manager, department, location and cost centre confirmed
- [ ] Role-based access requirements approved
- [ ] Special hardware, software or accessibility needs identified
- [ ] Asset owner and handover contact recorded

### Identity and access

- [ ] User account created through the approved identity workflow
- [ ] Correct groups, licences and application roles assigned
- [ ] Multi-factor authentication enrolment instructions prepared
- [ ] Initial credentials delivered through an approved secure channel
- [ ] Shared-mailbox or distribution-list access verified
- [ ] Excess permissions checked and removed

### Device preparation

- [ ] Asset tag and serial number recorded
- [ ] Approved operating-system image applied
- [ ] Updates, drivers and security controls verified
- [ ] Device joined to the approved directory or management platform
- [ ] Standard applications installed
- [ ] Encryption, endpoint protection and compliance status confirmed
- [ ] Dock, monitors, headset and other peripherals tested

### Handover

- [ ] User identity verified before handover
- [ ] Device and accessories acknowledged
- [ ] First login completed
- [ ] Email, collaboration, VPN and required applications tested
- [ ] Support contact and self-service resources explained
- [ ] Ticket updated with completion evidence

## Offboarding

### Request validation

- [ ] Approved leaving date and access-cutoff time confirmed
- [ ] Manager and HR/security instructions recorded
- [ ] Legal hold or data-retention requirements checked
- [ ] Ownership transfer for mailboxes, files and applications approved

### Access control

- [ ] Interactive sign-in disabled at the approved time
- [ ] Active sessions and tokens revoked when required
- [ ] Group, application and privileged access removed
- [ ] Shared secrets, keys or service credentials rotated when applicable
- [ ] Forwarding or delegated access configured only with approval
- [ ] Account retention/deletion scheduled according to policy

### Asset recovery

- [ ] Laptop, mobile device and peripherals recovered
- [ ] Asset condition and missing items recorded
- [ ] Device isolated from reassignment until processing is complete
- [ ] Required business data preserved through an approved workflow
- [ ] Device wiped with an approved tool and evidence recorded
- [ ] Asset inventory and stock location updated

### Closure

- [ ] All tasks independently reviewed when policy requires it
- [ ] Exceptions and missing assets escalated
- [ ] Completion communicated to authorised stakeholders
- [ ] Ticket closed with approvals, evidence and final status

## Control principles

- Use least privilege and role-based access.
- Never send passwords through ordinary email or ticket comments.
- Do not wipe a device until retention and ownership requirements are confirmed.
- Record asset identifiers and approvals, but avoid unnecessary personal data.
- Separate requester, approver and executor roles where organisational policy requires it.
